# V5.8.1 afterCommit Semantics Proof

Date: 2026-05-13
Stage: V5.8.1 Review Remediation
Priority: P0

## Bug Description

Before fix: Transaction commit did not clearly separate DB commit success from afterCommit callback failure. If an
afterCommit callback threw, the exception message said "Failed to commit transaction" — misleading because the DB commit
had already succeeded.

## Root Cause

The commit() method did not:

1. Decrement transaction nesting before running callbacks
2. Clear callback queue before execution
3. Distinguish DB commit failure from afterCommit callback failure

## Fix

Rewrote `Transaction::commit()`:

1. On outermost commit (transactions === 1):
    - Execute SQL COMMIT
    - Snapshot and clear afterCommit callbacks (so they can't run twice)
    - Decrement transaction counter
    - Fire TransactionLifecyclePhase::Committed event
    - Run each callback with individual try/catch
    - If callback fails: fire AfterCommit event with error, throw "AfterCommit callback failed:"
    - If all callbacks succeed: fire AfterCommit event with no error

2. Key invariant: afterCommit callbacks only run on outermost commit.
3. Key invariant: DB commit success is independent of callback success.

## Proof

- `transaction_committed_event_fires_before_after_commit_callbacks` — Ordering proof
- `transaction_after_commit_callbacks_run_only_on_outermost_commit` — Nested transaction proof
- `transaction_after_commit_callback_failure_does_not_rollback_db` — Failure isolation proof
- `transaction_after_commit_failure_message_distinguishes_callback_error` — Error semantics proof

### Gate Evidence

- Gate 3: "TransactionLifecyclePhase::AfterCommit is distinct from Committed"
- Gate 3: "Transaction has afterCommit callback storage"
- Gate 3: "commit() fires Committed event, runs callbacks, then fires AfterCommit event"

## Verdict

P0 FIXED. Clear separation: DB commit (Committed event) vs afterCommit callbacks (AfterCommit event).
