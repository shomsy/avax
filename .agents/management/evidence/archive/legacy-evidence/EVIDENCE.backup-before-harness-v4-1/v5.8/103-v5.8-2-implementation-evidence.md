# V5.8.2 Whole-System Runtime Cohesion — Implementation Evidence

Date: 2026-05-13

## Summary

V5.8.2 is a whole-system hardening pass. It does not add features. It removes cheap-code seams, converges runtime
resolution, fixes security drift, and strengthens governance.

## Changes Made

### 1. Central Runtime Callable Resolver

**Created:**

- `components/Application/Container/System/Capabilities/ResolveCallable/ResolveCallable.php` — Central
  callable/class-string resolution
- `components/Application/Container/System/Capabilities/ResolveCallable/CallableResolutionFailed.php` — Resolution
  failure exception
- `tests/Unit/Components/Application/Container/ResolveCallable/ResolveCallableTest.php` — 10 tests

**API:**

```php
$resolver = new ResolveCallable(?ContainerInterface $container = null);
$callable = $resolver->resolve($listener);  // class-string or callable
$result = $resolver->invoke($listener, [$arg1, $arg2]);
```

**Resolution order:**

1. Callable → return as-is
2. Class-string + container available → container::get()
3. Class-string + no container → zero-arg `new`
4. Non-invokable class → throw CallableResolutionFailed

### 3. Database Lifecycle Runtime Migration

**Modified:**

- `components/DataStack/Database/System/Capabilities/ORM/Persisters/EntityPersister.php` — dispatchEntityEvent uses
  ResolveCallable
- `components/DataStack/Database/System/Capabilities/Query/Execution/QueryOrchestrator.php` — dispatchQueryLifecycle and
  checkSlowQuery use ResolveCallable
- `components/DataStack/Database/System/Capabilities/Transactions/RunTransaction/Transaction.php` —
  dispatchTransactionLifecycle uses ResolveCallable

**Before:** `new $listener()` in 3 DB lifecycle dispatch methods
**After:** `ResolveCallable->resolve($entry['listener'])` in all 3

**Slow query fix:** checkSlowQuery now uses `RedactBindings::redact($bindings)` — same redaction path as normal
executed/failed events. Previously passed raw bindings to slow query event.

**Tests:** 100 DB lifecycle tests GREEN

### 4. QueryExecuted Semantic Convergence

**Before:** Two QueryExecuted classes with different payload security:

- `Telemetry/Events/QueryExecuted` — has `rawBindings` public property (security risk)
- `Foundation/Lifecycle/Events/QueryExecuted` — bindings redacted at source

**After:** The lifecycle QueryExecuted remains canonical for DB lifecycle events. The telemetry QueryExecuted still
exists in Telemetry/Events for the telemetry lane but:

- Slow query path now uses lifecycle QueryExecuted with redacted bindings
- QueryOrchestrator no longer passes raw bindings to any lifecycle event
- The telemetry QueryExecuted with rawBindings is isolated to the telemetry path only

### 5. Transaction afterCommit Semantics

**Status:** Already correct from V5.8.1. Verified:

- DB commit wrapped in try/catch
- afterCommit callbacks run outside DB commit catch
- Callback failure throws "AfterCommit callback failed:" not "Failed to commit transaction"
- Committed event fires before callbacks

### 6. Echo Removal

**Fixed:** `QueryOrchestrator::logPretend()` — removed `echo` statement. Pretend mode is now silent. To inspect queries,
wrap with logging decorator.
