## 2. Boot Phase Classification

| Phase                          | Current owner                                                  | Status                                                                                       |
|--------------------------------|----------------------------------------------------------------|----------------------------------------------------------------------------------------------|
| 1. Declaration                 | `Avax::boot(ApplicationBuilder)` / `Avax::create()`            | **Present but manual** — user must construct ApplicationBuilder or accept hardcoded defaults |
| 2. Configuration collection    | `ApplicationBuilder` fields                                    | **Present** — but collected via fluent builder, not config files + DSL                       |
| 3. Provider registration       | `ApplicationBuilder::registerComponentProvider()`              | **Partial** — user must manually register providers, no scanning                             |
| 4. Container compile           | None                                                           | **ABSENT** — no compile phase exists                                                         |
| 5. Container verify            | None                                                           | **ABSENT** — no verify phase exists                                                          |
| 6. Container freeze            | None                                                           | **ABSENT** — no freeze phase exists                                                          |
| 7. Provider boot               | `ComponentRegistry::boot()`                                    | **Present** — but separate from container lifecycle                                          |
| 8. Runtime object creation     | `BuildApplicationState::build()` / `CreateApplication::make()` | **Present** — but manual construction, not container-resolved                                |
| 9. Request/job/event execution | `Runtime` / `App` / `HttpKernel`                               | **Present** — receives already-assembled Runtime                                             |

---

## 3. Key Problems

1. **No root container lifecycle**: Container exists but no one owns compile → verify → freeze → boot → run.
2. **No provider scanning**: 55+ ServiceProviders exist but nothing discovers and boots them in order.
3. **Manual construction everywhere**: `Avax::create()` and `Avax::boot()` manually `new` everything.
4. **Runtime-adjacent code assembles**: `Avax` class (a facade) creates services — violates DI law.
5. **ApplicationBuilder is a collector, not an orchestrator**: It gathers options but doesn't drive container lifecycle.
6. **Container compile/verify/freeze is completely absent**: Dependencies fail at runtime, not at boot.
7. **Golden path apps teach manual assembly**: Examples show `new ApplicationBuilder(...)` with many params.

---

## 4. What Must Change for V5.9

- Boot DSL must own phases 1-8.
- Runtime must only receive phase 9 (already assembled graph).
- Container must own compile/verify/freeze.
- Provider scanning must be automatic.
- `Avax` facade must delegate to Boot DSL, not manually construct.

---

## 5. What Must NOT Change in This First Slice

- Runtime execution path (App, Runtime, HttpKernel, ConsoleKernel) — receive ready graph.
- Individual ServiceProviders — keep registering as-is.
- ContainerInterface — keep existing API.
- ComponentRegistry — keep provider registration, integrate with container.
- Golden path examples — update to use Boot DSL after it exists.
