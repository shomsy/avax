## Bug Description

Before fix: Query lifecycle event docblocks claimed "SQL and bindings are redacted by default" but QueryOrchestrator::
buildQueryEvent() passed raw bindings directly into QueryExecuting/QueryExecuted/QueryFailed events.

## Root Cause

No redaction utility existed. The docblocks described intended behavior, not actual behavior.

## Fix

Created `RedactBindings` static utility:

```php
final class RedactBindings {
    public const SENSITIVE_KEYS = ['password', 'passwd', 'pass', 'token', 'secret', 'api_key', ...];

    public static function redact(array $bindings): array;  // auto-detects named vs positional
}
```

Redaction rules:

- Named bindings: redact any key containing a sensitive keyword
- Positional bindings: detect Bearer tokens, JWT patterns, 32+ hex strings
- Auto-detects named (string keys) vs positional (integer keys)

Wired into `QueryOrchestrator::buildQueryEvent()`:

```php
$redactedBindings = RedactBindings::redact($bindings);
```

## Proof

### Unit Tests (5 tests)
