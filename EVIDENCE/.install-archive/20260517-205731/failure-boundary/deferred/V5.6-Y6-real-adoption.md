## OnFailure Adoption Proof

| Exception | HTTP Status | Message Key | Test |
|---|---|---|---|
| `ValidationFailed` | 422 | `validation_failed` | `onfailure_maps_validation_failed_to_422` |
| `ExternalServiceDown` | 503 | `external_service_down` | `onfailure_maps_external_service_down_to_503` |
| Unmapped `LogicException` | Propagates | N/A | `unmapped_exception_propagates_not_swallowed` |

### Attribute Configuration

```php
#[OnFailure(ValidationFailed::class, respondWith: 422, messageKey: 'validation_failed')]
#[OnFailure(RegistrationFailed::class, respondWith: 409, messageKey: 'registration_failed')]
#[ReportFailure(channel: 'http')]
public function register(array $input): ResponseInterface
```

```php
#[OnFailure(ExternalServiceDown::class, respondWith: 503, messageKey: 'external_service_down')]
#[ReportFailure(channel: 'http')]
public function verifyIdentity(string $provider): ResponseInterface
```

## Why This Is Not Decorative

1. **Real domain exceptions** — `ValidationFailed`, `RegistrationFailed`, `ExternalServiceDown` are real domain exceptions, not test fixtures
2. **Real HTTP mapping** — Each exception maps to a specific HTTP status code (422, 409, 503)
3. **Real middleware wiring** — FailureBoundary middleware is wired into the App pipeline
4. **Behavior proven by removal** — Test proves removing the attribute changes behavior
5. **No deferred attributes** — Only `OnFailure` and `ReportFailure` are used (no Retry, Timeout, RecoverWith)
6. **No sensitive data leaks** — Test proves password values don't leak into error responses
7. **No hot-path reflection** — Test proves compilation is cached, runtime uses zero reflection
