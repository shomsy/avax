## Final Owner Decisions

| Domain | Canonical Owner | Path | Rationale |
|--------|----------------|------|-----------|
| Canonical DB owner | Database | `components/DataStack/Database/` | Already owns QueryBuilder, ORM, Transactions, Connections, Telemetry |
| Lifecycle owner | Database — Lifecycle capability | `components/DataStack/Database/System/Capabilities/Lifecycle/` | Lifecycle IS a DB capability. Lives within existing canonical DB owner. |
| Transaction lifecycle owner | Database — Transaction capability | `components/DataStack/Database/System/Capabilities/Transactions/` | Already owns Transaction.php. afterCommit/afterRollback extend transaction behavior. |
| Outbox bridge owner | Operations/Outbox (future) | `components/Operations/Outbox/` | Outbox is delivery reliability, not core DB. Depends on DB lifecycle for afterCommit trigger. |
| Projection bridge owner | Operations/MessageBus (existing) + Operations/Projections (future) | `components/Operations/MessageBus/System/Capabilities/Projection/` | MessageBus already has Projection capability. Future dedicated component for CQRS read models. |
| Future EventStore owner | Future separate capability | `components/DataStack/EventStore/` or `components/Operations/EventSourcing/` | EventStore is source-of-truth storage. Separate from lifecycle, outbox, and projections. Not V5.8 scope. |
| Future EventSourcing owner | Future separate capability | `components/Operations/EventSourcing/` | Event Sourcing Kit needs aggregates, streams, snapshots, upcasters. Not V5.8 scope. |

## What Must Not Be Duplicated

- **Do not create** `components/DataStack/DatabaseLifecycle/` as top-level sibling — lifecycle is a Database capability, not a separate component.
- **Do not create** `components/Operations/Events/DatabaseLifecycle/` — Events dispatches, it does not own DB internals.
- **Do not create** a second event dispatcher for DB lifecycle — DB lifecycle may emit through canonical Events, but must not create a parallel generic event system.
- **Do not duplicate** Transaction behavior — extend existing `Transaction.php` with afterCommit/afterRollback hooks.
- **Do not duplicate** QueryBuilder behavior — integrate lifecycle hooks at natural execution boundaries.
- **Do not duplicate** ORM behavior — integrate entity lifecycle at UnitOfWork/EntityPersister boundaries.

## Expected Dependency Direction

```
components/DataStack/Database/          ← owns DB lifecycle, transaction lifecycle, query lifecycle
    ↓
components/Operations/Events/           ← DB lifecycle may emit canonical events through Events
    ↓
components/Operations/Outbox/ (future)  ← depends on DB lifecycle for afterCommit trigger
    ↓
components/Operations/MessageBus/       ← existing Projection capability, depends on Events
```
