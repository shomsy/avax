## Bug Description

Before fix: Each DSL class (EntityLifecycleDsl, QueryLifecycleDsl, TransactionLifecycleDsl) had its own private static
`$registry`. Runtime classes (EntityPersister, QueryOrchestrator, Transaction) created new
`CompiledDatabaseLifecycleRegistry` instances. DSL registrations never reached runtime dispatchers.

## Root Cause

Three separate registry instances:

1. EntityLifecycleDsl::$registry (static private)
2. QueryLifecycleDsl::$registry (static private)
3. TransactionLifecycleDsl::$registry (static private)
4. EntityPersister constructor default: `new CompiledDatabaseLifecycleRegistry()`
5. QueryOrchestrator constructor default: `new CompiledDatabaseLifecycleRegistry()`
6. Transaction constructor default: `new CompiledDatabaseLifecycleRegistry()`

## Fix

Created `GlobalDatabaseLifecycleState` — a boot-time singleton:

```php
final class GlobalDatabaseLifecycleState {
    private static ?CompiledDatabaseLifecycleRegistry $registry = null;

    public static function registry(): CompiledDatabaseLifecycleRegistry { ... }
    public static function setRegistry(CompiledDatabaseLifecycleRegistry $registry): void { ... }
    public static function freeze(): void { ... }
    public static function isFrozen(): bool { ... }
    public static function reset(): void { ... } // testing only
}
```

All DSL classes now use `GlobalDatabaseLifecycleState::registry()`.
All runtime classes use nullable registry + `getRegistry()` fallback to global.

## Proof

### Unit Tests (4 tests)

- `runtime_uses_global_registry_by_default` — EntityPersister without explicit registry uses global
- `dsl_and_runtime_share_same_registry_instance` — Same instance from DSL and runtime
- `global_state_freeze_prevents_registration` — Frozen registry rejects new registrations
- `global_state_reset_for_testing` — Reset clears global state

### Gate Evidence

## Verdict

P0 FIXED. Single `GlobalDatabaseLifecycleState` singleton shared by DSL and runtime.
