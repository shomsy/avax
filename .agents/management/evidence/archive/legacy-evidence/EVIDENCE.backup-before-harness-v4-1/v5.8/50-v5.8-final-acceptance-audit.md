## What V5.8 Implements

- **Entity lifecycle DSL**:
  `onEntity(User::class)->creating()->created()->updating()->updated()->saving()->saved()->deleting()->deleted()->restored()->failedToSave()->failedToDelete()`
- **Transaction lifecycle DSL**:
  `onTransaction()->beginning()->committed()->afterCommit()->rolledBack()->afterRollback()->failed()`
- **Query lifecycle DSL**: `onQuery()->executing()->executed()->slow(thresholdMs: N)->failed()`
- **Compiled registry**: Single frozen registry, priority descending, registration order tie-break, no runtime
  reflection
- **Transaction afterCommit/afterRollback**: Buffer callbacks, run on outermost commit, discard on rollback,
  no-transaction policy runs immediately
- **Outbox groundwork**: OutboxMessageStatus, OutboxMessageId, OutboxMessage (design)
- **17 lifecycle event objects**: EntityCreating, EntityCreated, EntityUpdating, EntityUpdated, EntitySaving,
  EntitySaved, EntityDeleting, EntityDeleted, EntityRestored, FailedToSave, FailedToDelete, TransactionBeginning,
  TransactionCommitted, AfterCommit, TransactionRolledBack, AfterRollback, QueryExecuting, QueryExecuted, QueryFailed
- **5 lifecycle enums**: EntityLifecyclePhase, QueryLifecyclePhase, TransactionLifecyclePhase, LifecycleSource,
  LifecycleExecutionMode

## Security

- No secrets logged, reported, or returned
- SQL bindings are typed in event objects (redaction applied at documentation level)
- Listener exceptions bubble by default — no silent swallowing
- afterCommit callbacks cleared on rollback — no post-rollback external side effects

## Performance

- No-listener fast path: registry returns empty array instantly
- No runtime attribute reflection — compile-time only
- Priority sorting done at registration time, not at resolution time
- Frozen registry prevents runtime mutation
