# V5.8.1 Review Remediation — Truth Check

**Date:** 2026-05-13
**Stage:** V5.8.1 Database Lifecycle Code Review Remediation
**Initial Classification:** FULL_GREEN_SUSPENDED_PENDING_REMEDIATION

## Reason

Code review found concrete behavior bugs and evidence/docs drift after V5.8 closure:

### P0 Bugs Found

1. **Duplicate saving/saved dispatch** — CONFIRMED BUG
    - `EntityPersister::insert()` dispatches `[Creating, Saving]` phases before SQL and `[Created, Saved]` after
    - `CompiledDatabaseLifecycleRegistry::entityListenersFor()` does superset expansion: for `Creating` it also returns
      `Saving` listeners
    - Result: on insert, a listener registered for `Saving` runs TWICE (once from explicit Saving dispatch, once from
      superset expansion of Creating)
    - Same bug for `Saved` on insert (via Created superset) and `Saved` on update (via Updated superset)

2. **Public DSL registry wiring** — CONFIRMED BUG
    - DSL classes use `self::$registry` static property
    - `EntityPersister` and `QueryOrchestrator` default to `new CompiledDatabaseLifecycleRegistry()` (separate instance)
    - Unless `EntityLifecycleDsl::setRegistry()` is called AND the same registry is injected into runtime classes, they
      are separate registries
    - `Transaction::on()` also creates `new CompiledDatabaseLifecycleRegistry()` when no registry is passed

3. **Query binding redaction** — CONFIRMED BUG
    - Event objects `QueryExecuting`, `QueryExecuted`, `QueryFailed` store raw `$bindings` as public properties
    - No redaction is applied anywhere
    - Docblocks say "redacted by default" but code does NOT redact

4. **Transaction afterCommit failure semantics** — NEEDS CLARIFICATION
    - If afterCommit callback fails, `TransactionException` wraps it as "Failed to commit transaction" AFTER commit
      already happened
    - This is misleading — the DB commit succeeded, only the callback failed

### P1 Issues

5. **Weak tests** — `assertTrue(true)` found in DSL tests
6. **Gates are shape-only** — most gates check class/file existence, not behavior
7. **Stale evidence/docs** — CURRENT_TRUTH says 8231 tests, baseline says 8231, ledger says 8203
8. **Decorative phases** — `TransactionLifecyclePhase::Failed` exists but throws runtime error if dispatched directly

## Files Requiring Changes

- `EntityLifecycleDsl.php` — wire shared registry
