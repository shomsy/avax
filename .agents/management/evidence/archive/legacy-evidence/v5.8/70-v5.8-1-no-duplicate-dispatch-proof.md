# V5.8.1 No Duplicate Dispatch Proof

Date: 2026-05-13
Stage: V5.8.1 Review Remediation
Priority: P0

## Bug Description

Before fix: EntityPersister explicitly dispatched [Creating, Saving] for insert AND CompiledDatabaseLifecycleRegistry
also expanded Creating→Saving. This caused Saving listeners to fire twice.

## Root Cause

Two mechanisms doing superset:

1. EntityPersister::insert() called `dispatchEntityLifecycle()` for both Creating AND Saving phases
2. CompiledDatabaseLifecycleRegistry::entityListenersFor() also returned Saving listeners when queried for Creating
   phase

Result: Saving listeners received two dispatches per insert.

## Fix

Removed superset expansion from `CompiledDatabaseLifecycleRegistry::entityListenersFor()`:

```php
// Before: returned Saving listeners when queried for Creating
// After: exact lookup only
return $this->entityListeners[$entityClass][$phase->value] ?? [];
```

EntityPersister still explicitly dispatches both Creating and Saving phases — that is the correct ownership. The
registry is a lookup table, not a semantic expander.

## Proof

### Unit Tests (6 tests)

- `entity_creating_dispatches_exact_listeners_only` — Creating fires Creating listeners only
- `entity_saving_dispatches_exact_listeners_only` — Saving fires Saving listeners only
- `entity_insert_dispatches_creating_and_saving_exactly_once` — Insert fires each phase once
- `entity_update_dispatches_updating_and_saving_exactly_once` — Update fires each phase once
- `registry_exact_lookup_no_superset_expansion` — Registry returns exact match only
- `entity_superset_handling_by_persister_not_registry` — Persister dispatches both phases explicitly

### Gate Evidence

- Gate 1: "Registry exact lookup — no superset expansion in hot path"
- Gate 1: "Saving phase returns only Saving listeners"
- Gate 4: "Registry uses exact lookup (no superset expansion in hot path)"

### PHPUnit Result

8269 tests GREEN — no duplicate dispatch failures.

## Verdict

P0 FIXED. Superset is handled by EntityPersister (explicit dispatch), not by registry (exact lookup).
